# MINI-16: Заключение и цена

## Цель
Итог отчёта — текстовое заключение и цена в BYN.

## Контекст
- **Источник:** `PLAN_FRONTEND_MINIAPP.md`, раздел 2.8 (`PUT .../conclusion`), фича MINI-16
- **Бэкенд:** ✅ готово

## Зависимости
- MINI-08

## Требования

### Экран `/reports/:id/conclusion`
Текст заключения (с подсказкой-шаблоном: плюсы, минусы, рекомендация), цена в BYN (ввод «50» или «49,90» → копейки), автосохранение **только при заполненных обоих полях**.

### Контракт
`PUT /inspector/reports/{id}/conclusion`, тело `{ conclusionText, priceByn }`. **Оба поля обязательны** на бэкенде (`@NotBlank`, `@NotNull`) — автосохранение возможно только когда заполнены оба. `priceByn` — **в копейках**: «50» → `5000`, «49,90» → `4990`. Бэкенд не проверяет знак и минимум — `0` и отрицательные значения проходят. На фронте — минимум (рекомендация плана: 1 BYN) и разумный максимум.

## Acceptance Criteria
- [ ] «50» отправляется как `5000`, «49,90» — как `4990`
- [ ] цена `< 1` BYN или пустая не отправляется, показывается ошибка
- [ ] без текста или цены — состояние «На устройстве» (не ошибка)
- [ ] сохранённые значения восстанавливаются из `GET` (копейки → BYN, обратная конвертация)

## Gotchas
1. **`priceByn` в копейках** — конвертация в обе стороны должна быть в одном месте (утилита), не дублировать логику округления.
2. Оба поля обязательны на сервере — сохранить можно только когда оба заполнены, частичное сохранение не поддерживается до BE-14.
3. Бэкенд не валидирует диапазон цены — минимум и максимум держит только фронт.

## Промпт для агента
```
Реализуй экран заключения и цены согласно MINI-16-conclusion-price.md:

1. /reports/:id/conclusion: текст заключения (с подсказкой-шаблоном плюсы/минусы/рекомендация), поле цены в BYN
2. Конвертация BYN↔копейки в одной утилите (поддержка «50» и «49,90»)
3. Автосохранение PUT /inspector/reports/{id}/conclusion только когда оба поля заполнены
4. Клиентская валидация цены: минимум 1 BYN, разумный максимум
5. Восстановление из GET: копейки → BYN при отображении

Проверь все acceptance criteria, особенно точность конвертации копеек (49,90 → 4990, не 4989 или 4991 из-за округления floating point).
```
