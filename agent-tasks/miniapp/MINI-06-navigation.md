# MINI-06: Навигация и главная

## Цель
Оболочка для верифицированного подборщика: таб-бар, список отчётов из временного локального индекса.

## Контекст
- **Источник:** `PLAN_FRONTEND_MINIAPP.md`, раздел 1.1 (сценарий I), раздел 3.3 п.9 (локальный индекс), фича MINI-6
- **Бэкенд:** ❌ эндпоинта «мои отчёты» нет (BE-7) — используется временный локальный индекс

## Зависимости
- MINI-05

## Требования

### Таб-бар
`Отчёты / Спрос / Профиль` на telegram-ui `Tabbar`. BackButton скрыт на всех трёх табах.

### `/reports` — временная реализация без BE-7
Пока нет `GET /inspector/reports` (BE-7), список строится по **локальному индексу** `podbor:reports-index` (`[{reportId, avbyUrl, createdAt}]`, раздел 3.3 п.9), который пополняется после каждого `POST /inspector/reports` (реализуется в MINI-07). Для каждого `reportId` из индекса делается `GET /inspector/reports/{id}` и показывается статус.

Кнопка «Новый отчёт» → `/reports/new` (MINI-07).

### `/demand` — заглушка
«Скоро» — полноценная реализация в MINI-20 (ждёт BE-15).

## Acceptance Criteria
- [ ] табы переключаются, BackButton на табах скрыт
- [ ] созданный на этом устройстве отчёт появляется в списке со статусом (черновик, на модерации, на доработке, опубликован)
- [ ] отчёт, получивший `404` при перезапросе, исчезает из индекса с пометкой «удалён»
- [ ] пустое состояние с подсказкой «Создайте первый отчёт»
- [ ] `/demand` показывает заглушку, не ломается

## Gotchas
1. **Список отчётов — временный, локальный и привязан к устройству.** Отчёт, созданный на другом телефоне (переустановка, смена устройства), не появится здесь до MINI-19/BE-7. Явно предупреждать пользователя не нужно для MVP, но код должен быть написан так, чтобы замена на серверный список (MINI-19) была локальной правкой одного экрана, а не переписыванием стора.
2. Хранить индекс отдельно от черновика (`podbor:draft:<id>`, MINI-08) — это разные сущности с разным жизненным циклом.

## Промпт для агента
```
Реализуй навигацию и главный экран подборщика согласно MINI-06-navigation.md:

1. Taskbar на telegram-ui Tabbar: Отчёты / Спрос / Профиль, BackButton скрыт на всех трёх
2. /reports: читает локальный индекс podbor:reports-index из localStorage, делает GET /inspector/reports/{id} для каждого элемента, показывает статус карточками
3. Кнопка «Новый отчёт» → /reports/new
4. Отчёт с 404 при перезапросе — убрать из индекса, показать «удалён» перед удалением (не мгновенно)
5. Пустое состояние «Создайте первый отчёт»
6. /demand: заглушка «скоро» (полная реализация в MINI-20)

Структурируй код так, чтобы в MINI-19 /reports можно было переключить на серверный список без переписывания остальной логики (например, через единый хук useMyReports(), который сейчас читает локальный индекс).

Проверь acceptance criteria.
```
