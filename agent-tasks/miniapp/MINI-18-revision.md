# MINI-18: Доработка после `revision_required`

## Цель
Замкнуть цикл модерации: подборщик видит причину доработки (если доступна) и повторно отправляет отчёт.

## Контекст
- **Источник:** `PLAN_FRONTEND_MINIAPP.md`, раздел 1.1 (сценарий H), фича MINI-18
- **Бэкенд:** 🟡 частично — редактирование `revision_required` работает (как и `draft`), но причина доработки недоступна через API (BE-8), уведомление с глубокой ссылкой недоступно без BE-16/BOT-03

## Зависимости
- MINI-17. 🟡 BE-8 (причина) и BE-16/BOT-03 (уведомление) — улучшения.

## Требования

### Баннер «Требуются правки»
В хабе (`/reports/:id`) и в мастере — с причиной из `lastModeration` (**требует BE-8**, без него — «Причина — в сообщении от бота», не выдумывать текст).

### Поведение
Те же шаги мастера, в режиме редактирования (как `draft`, раздел 2.8: редактируемы только `draft` и `revision_required`). Повторная отправка — через MINI-17. Вход — по `startapp=report_<id>` и по web_app-кнопке уведомления (готовится в BOT-02/BOT-03).

## Acceptance Criteria
- [ ] отчёт в `revision_required` редактируется, а `pending_review` — нет
- [ ] причина видна, если бэкенд её отдаёт (после BE-8); до этого — нейтральный текст без выдумывания причины
- [ ] повторная отправка переводит отчёт в `pending_review`
- [ ] глубокая ссылка из уведомления открывает именно этот отчёт

## Gotchas
1. **Причина доработки недоступна через `/inspector/**` до BE-8** — лежит только в `moderation_log`, видна админу, не подборщику через API. Не подменять реальным текстом, если его нет в ответе.
2. Статусы, допускающие редактирование — строго `draft` и `revision_required`, остальные — только чтение (это уже реализовано в MINI-08/MINI-09, здесь — повторная проверка на конкретном сценарии).

## Промпт для агента

Реализуй доработку отчёта после revision_required согласно MINI-18-revision.md:

1. Баннер «Требуются правки» в хабе и мастере, причина из report.lastModeration (если поле присутствует после BE-8), иначе — нейтральный текст «Причина — в сообщении от бота»
2. Убедись, что мастер редактируем для revision_required так же, как для draft (используя уже реализованную в MINI-08/09 логику режима чтения)
3. Повторная отправка — через существующий флоу MINI-17 (review → submit)
4. Проверь, что startapp=report_<id> (MINI-02) корректно открывает конкретный отчёт в режиме редактирования
