# MINI-13: Фото в секциях и обязательные фото

## Цель
UI съёмки и галереи в мастере, включая стартовый экран с обязательными фото.

## Контекст
- **Источник:** `PLAN_FRONTEND_MINIAPP.md`, раздел 2.9 (конец, про обязательные фото), раздел 1.2 (`/reports/:id/start`), фича MINI-13
- **Бэкенд:** ❌ обязательные фото не выделены в модели вообще (BE-11), ❌ удаление медиа нет (BE-12) — оба P1, не блокируют реализацию, но ограничивают её

## Зависимости
- MINI-12. Без BE-11 теги видны только на этом устройстве, без BE-12 нельзя удалить, без бэкенд-фичи B-39 (см. MINI-12) миниатюра не покидает устройство.

## Требования

### Экраны и компоненты
- Блок фото на шаге секции: кнопки «Камера» и «Галерея», сетка миниатюр со статусом загрузки, полноэкранный просмотр.
- `/reports/:id/start`: слоты «Одометр», «VIN-табличка», «Подборщик у машины», «Документы» — это **глобальные фото** (`sectionId = null`) с локальным тегом в `localMediaTags` (часть черновика, раздел 3.3), **до BE-11 бэкенд их не отличает** — в превью они окажутся в общей галерее, а не в выделенных слотах.
- **Подтверждение перед загрузкой** («Загрузить это фото?») — обязательно, потому что удалить медиа невозможно (BE-12 не реализован). Как только появится BE-12 — заменить на кнопку «Удалить» у уже загруженного фото (без потери подтверждения перед первой загрузкой — продуктовое решение, не менять по умолчанию).

### Принятый риск S-22 (зафиксирован в плане, не чинить самостоятельно)
Клиентская миниатюра может **не совпадать** с полным фото (подмена в сетке), потому что миниатюра и полное фото — разные независимые загрузки, и сервер их не связывает до бэкенд-фичи B-39. Вариант принят сознательно (техдолг зафиксирован как B-97) — доверие проверенным подборщикам. **Не реализовывать собственную проверку соответствия**, это осознанный компромисс продукта.

## Acceptance Criteria
- [ ] фото секции попадают в `sections[].media` нужной секции
- [ ] слоты обязательных фото показывают «заполнено», когда фото загружено
- [ ] перед загрузкой показывается превью с подтверждением
- [ ] после перезагрузки миниатюры своих фото на месте (из памяти очереди/локального кеша в рамках MVP — раздел 3.4)
- [ ] в отчёте только для чтения кнопок съёмки нет

## Gotchas
1. **Обязательные фото — только локальный тег до BE-11.** Бэкенд видит их как обычные глобальные фото. Не выдавать в UI уверенность, которой нет на сервере (например, не блокировать `submit`, опираясь только на локальный тег — чек-лист в MINI-17 делает это предупреждением, не блокером, до BE-11).
2. **Нет удаления медиа (BE-12)** — ошибочное фото навсегда остаётся в отчёте. Подтверждение перед загрузкой — не UX-украшение, а единственная защита.
3. **S-22 принятый риск** — миниатюра может не совпадать с полным фото, это осознанно, не исправлять самостоятельно.

## Промпт для агента
```
Реализуй фото в секциях и стартовый экран обязательных фото согласно MINI-13-mandatory-photos.md:

1. Блок фото на шаге секции: кнопки «Камера»/«Галерея», сетка миниатюр со статусом, полноэкранный просмотр
2. /reports/:id/start: 4 слота (Одометр, VIN-табличка, Подборщик у машины, Документы) — глобальные фото (sectionId=null) с локальным тегом localMediaTags (часть ReportDraft из MINI-08)
3. Подтверждение «Загрузить это фото?» перед постановкой в очередь (единственная защита, пока нет удаления медиа)
4. В режиме только для чтения — скрыть кнопки съёмки

Явно задокументируй в коде (комментарий), что:
- обязательность фото не проверяется сервером до BE-11 — только локальный тег
- миниатюра может не совпадать с полным фото (S-22/B-97) — это принятый риск, не технический долг для исправления в этой задаче

Проверь все acceptance criteria.
```
