# MINI-23: Очередь загрузок в IndexedDB (второй этап)

## Цель
Загрузки переживают закрытие Mini App, а не только плохую сеть при открытом приложении.

## Контекст
- **Источник:** `PLAN_FRONTEND_MINIAPP.md`, раздел 3.4 (полная версия с IndexedDB), решение 2026-09-29 п. 3 (перенос во второй этап), фича MINI-23
- **Статус:** **второй этап**, явно отложено. MINI-11 реализует упрощённую MVP-версию (очередь в памяти).
- **Бэкенд:** не блокирует

## Зависимости
- MINI-11, MINI-12

## Требования
Перевод стора очереди из MINI-11 на IndexedDB (обёртка `idb-keyval` или `idb`), store `uploads`, по полной модели `UploadTask` из раздела 3.4 плана:
- восстановление задач при старте: все задачи в `presigning`, `uploading` и `confirming` возвращаются в `queued`, **кроме** `confirming` с известным `s3Key` — для неё сначала проверка через `GET` (как уже делается в MINI-10/11 для одиночного сбоя, здесь — то же правило при холодном старте);
- миниатюры из IndexedDB (не только из памяти, как в MVP);
- квота: перед постановкой в очередь — `navigator.storage.estimate()`; на iOS WebView квота может быть маленькой, при `QuotaExceededError` — ошибка, новые файлы не принимаются до разгрузки очереди; `navigator.storage.persist()`, если API доступно;
- blob хранится в IndexedDB 7 дней после `done`, затем удаляется, миниатюра остаётся в кеше превью дольше.

## Acceptance Criteria
- [ ] Mini App закрыт посреди загрузки 5 фото → при повторном открытии оставшиеся догружаются, дублей в отчёте нет
- [ ] при переполнении квоты новые файлы не принимаются, показывается ошибка

## Gotchas
1. **Это замена хранилища, а не новая логика очереди** — жизненный цикл задачи, backoff, параллельность уже реализованы в MINI-11 (в памяти). Здесь меняется только персистентность.
2. Восстановление `confirming`-задач после холодного старта — повторяет правило MINI-10 («перед повтором confirm — сначала GET»), но применяется ко всем задачам сразу при старте, не только к одной сбойной.
3. Квота IndexedDB на iOS WebView может быть неожиданно маленькой — тестировать конкретно на iOS, не только на десктопе.

## Промпт для агента
```
Переведи очередь загрузок на IndexedDB согласно MINI-23-upload-queue-indexeddb.md (второй этап, после MVP).

Перед началом убедись, что MINI-11 (очередь в памяти) и MINI-12 (обработка фото) уже реализованы — эта задача меняет хранилище, не логику.

1. Замени zustand-стор без persist (MINI-11) на IndexedDB (idb-keyval или idb), store 'uploads', по модели UploadTask из раздела 3.4 плана
2. При старте приложения: задачи в presigning/uploading возвращаются в queued; задачи в confirming с известным s3Key — сначала GET отчёта, проверка наличия s3Key в media/globalMedia, затем либо done, либо queued
3. Миниатюры — из IndexedDB, не только из памяти
4. Проверка квоты через navigator.storage.estimate() перед постановкой в очередь, navigator.storage.persist() если доступно
5. QuotaExceededError — явная ошибка, блокировка новых файлов до разгрузки очереди
6. Blob удаляется через 7 дней после done, миниатюра остаётся дольше в кеше превью

Проверь acceptance criteria, включая сценарий закрытия Mini App посреди загрузки 5 фото.
```
