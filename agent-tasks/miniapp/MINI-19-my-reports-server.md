# MINI-19: Мои отчёты с сервера

## Цель
Полный список отчётов подборщика, видимый с любого устройства.

## Контекст
- **Источник:** `PLAN_FRONTEND_MINIAPP.md`, раздел 5 BE-7, фича MINI-19
- **Бэкенд:** ❌ **БЛОКЕР** — эндпоинта `GET /inspector/reports` нет вообще

## Зависимости
- MINI-06, **BE-7** (блокер)

## ⚠️ Блокер
Нет эндпоинта. Предлагаемый контракт (раздел 5, BE-7 — предложение, не факт): `GET /inspector/reports?status=draft,revision_required` (фильтр опционален), с ответом вида:
```json
[
  {
    "id": "5b0c…", "status": "revision_required", "versionNo": 1,
    "car": { "id": "0e7d…", "make": "Volkswagen", "model": "Passat", "year": 2017, "vin": "…", "avbyListingUrl": "…" },
    "priceByn": 5000,
    "createdAt": "…", "updatedAt": "…", "submittedAt": "…",
    "lastModeration": { "action": "revise", "reason": "Нет фото VIN-таблички", "at": "…" },
    "salesCount": 0
  }
]
```
Это требует новых колонок (`reports.updated_at`, `reports.submitted_at`), которых сейчас в БД нет. **Не реализовывать этот контракт на фронте как финальный, пока бэкенд не подтвердил реальную форму ответа** — писать типы и MSW-моки по этому предложению, но явно помечать как предположение.

## Требования (на момент появления BE-7)
`/reports` переводится на `GET /inspector/reports`: фильтры-чипы по статусу, карточка (машина, статус, дата изменения, цена, число продаж, причина доработки), **слияние с локальным индексом** (MINI-06) — локальный индекс остаётся fallback на случай, если серверный список по какой-то причине недоступен. Статус «удалён модератором» с причиной — только если бэкенд реализовал вариант с `status: "deleted"` вместо полного исчезновения записи (раздел 5, BE-7 рекомендует этот вариант).

## Acceptance Criteria
- [ ] отчёт, созданный на другом устройстве, виден в списке (после реализации BE-7)
- [ ] фильтры работают, по умолчанию сверху «на доработке», потом черновики
- [ ] у доработки видна причина, у удалённого — причина удаления (если бэкенд отдаёт)
- [ ] pull-to-refresh и перезапрос при `activated`
- [ ] пока BE-7 не реализован: экран **не ломается**, использует MINI-06 (локальный индекс) как единственный источник

## Gotchas
1. **Эндпоинта нет вообще** — это не ограничение существующего контракта, а отсутствие контракта. Делать на моках с чёткой пометкой «предположительный контракт BE-7», готовиться к изменению полей при реальной реализации.
2. Замена `/reports` с MINI-06 на MINI-19 должна быть локализована в одном хуке (`useMyReports()`, см. рекомендацию в MINI-06) — не переписывать весь экран.
3. Мягко удалённые отчёты — открытый вопрос: вернутся ли они вообще в списке (с `status: "deleted"`) или не вернутся — план рекомендует первый вариант, но это не согласованное решение.
