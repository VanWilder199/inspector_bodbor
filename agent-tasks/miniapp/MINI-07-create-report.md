# MINI-07: Создание отчёта по ссылке av.by

## Цель
Подборщик вставляет ссылку av.by и попадает в мастер заполнения отчёта.

## Контекст
- **Источник:** `PLAN_FRONTEND_MINIAPP.md`, раздел 1.1 (сценарий D), раздел 2.4 (`POST /inspector/reports`), фича MINI-7
- **Бэкенд:** 🟡 частично — эндпоинт работает (`AvByParser` + `CarService.findOrCreateByUrl`), но без валидации URL и дедупликации (BE-19)

## Зависимости
- MINI-06. 🟡 BE-19 и BE-3 — улучшения, не блокеры.

## Требования

### Экран `/reports/new`
- Поле URL + кнопка «Вставить» из буфера (`navigator.clipboard.readText()`, в Telegram iOS не всегда доступно);
- подстановка значения из `?url=` (приходит от бота, BOT-02);
- **клиентская нормализация перед отправкой**: `https`, хост в нижнем регистре, без query, фрагмента и завершающего `/`;
- **проверка домена** (`av.by`, `cars.av.by`) до отправки — иначе либо `500` (строка без схемы), либо лишний риск SSRF на бэкенде;
- MainButton «Создать отчёт» с лоадером, текст «Загружаем объявление с av.by…» (парсер синхронный, таймаут бэкенда 10 с — UI обязан это явно показывать, а не висеть молча);
- запись `reportId` в локальный индекс (MINI-06) после успеха;
- переход на `/reports/:id`.

### Контракт (раздел 2.4)
`POST /inspector/reports`, тело `{ avbyUrl }` (`@NotBlank`). Ответ `200 { reportId }` — **данных машины в ответе нет** (ни марки, ни модели — показать «VW Passat 2017» в Mini App сейчас нечем, это BE-8).

Порядок на бэкенде: поиск машины по **точному совпадению строки** `avby_listing_url` → если есть, парсер не вызывается, переиспользуется `carId`; если нет — парсинг (Jsoup, таймаут 10 с) → `INSERT ... ON CONFLICT DO NOTHING`. Затем создаётся отчёт (`status=draft`) и 7 секций.

### Ошибки (таблица)
| Код | HTTP | Когда |
|---|---|---|
| `CAR_LISTING_NOT_FOUND` | 404 | av.by ответил 404 |
| `PARSER_ERROR` | 502 | другой HTTP-статус av.by, таймаут/IO, либо на странице нет марки/модели |
| `INSPECTOR_BANNED` | 403 | подборщик забанен |
| `INSPECTOR_NOT_FOUND` | 404 | не зарегистрирован |
| `BAD_REQUEST` | 400 | пустой `avbyUrl` |
| `INTERNAL_SERVER_ERROR` | 500 | строка не URL (`"abc"` без схемы) — `Jsoup.connect` бросает `IllegalArgumentException`, никто не ловит |

### Правило «не повторять автоматически»
Уникальности `(car_id, inspector_id)` нет — **каждый вызов создаёт новый черновик** с новым `reportId`. Строки URL, отличающиеся хоть одним символом (`...1`, `...1?utm=tg`, `.../1/`), создают **разные** машины и не переиспользуют парсер. Правила для фронта:
- кнопка блокируется на время запроса (защита от двойного тапа);
- **при таймауте или сетевой ошибке POST не повторяется автоматически** — это создаст дубль. Предлагается «Проверить мои отчёты» вместо ретрая.

## Acceptance Criteria
- [ ] `https://cars.av.by/.../123?utm=x#a` отправляется как `https://cars.av.by/.../123`
- [ ] ссылка не на av.by не отправляется, показывается ошибка валидации до запроса к серверу
- [ ] `404 CAR_LISTING_NOT_FOUND`, `502 PARSER_ERROR`, `403 INSPECTOR_BANNED` дают понятные тексты
- [ ] при таймауте или сетевой ошибке POST **не повторяется автоматически**, предлагается «Проверить мои отчёты»
- [ ] двойной тап не создаёт два отчёта (кнопка заблокирована на время запроса)
- [ ] после успеха `reportId` лежит в локальном индексе, открыт хаб отчёта

## Gotchas
1. **Повторный `POST` создаёт новый черновик.** URL с любым отличием (query, fragment, trailing slash, регистр хоста) — это другая машина для бэкенда.
2. **Таймаут должен быть заметно больше серверных 10 с** (см. MINI-03 — 30 с для этого эндпоинта), и UI должен явно показывать длительное ожидание, а не казаться подвисшим.
3. Строка без схемы (`"abc"`) даёт `500`, а не `400` — клиентская проверка домена/схемы обязательна **до** отправки.
4. Данных машины в ответе нет — название машины в UI показать нельзя до BE-8, использовать заглушку («Автомобиль») или распарсенный URL.
