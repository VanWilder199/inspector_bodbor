# BOT-03: Уведомления подборщику (приёмка BE-16 со стороны клиента)

## Цель
Проверить, что уведомления бэкенда приходят в Telegram и ведут в правильное место Mini App.

## Контекст
- **Источник:** `PLAN_FRONTEND_MINIAPP.md`, раздел 4.6 (таблица уведомлений), раздел 5 BE-16, фича BOT-3
- **Бэкенд:** ❌ **БЛОКЕР** — канала `TELEGRAM` нет вообще. Сейчас `NotificationSender.notify` (судя по текущему git-статусу репозитория переименован/переработан в `NotificationSenderImpl`) работает только с email/логом; `Channel.java` не содержит `TELEGRAM`

## Зависимости
- **BE-16** (блокер), MINI-18 (экран доработки, куда ведут кнопки уведомлений), BOT-02 (deep links)

## ⚠️ Блокер
Это полностью серверная фича: `TelegramBotClient` на `RestClient`, вызовы `POST https://api.telegram.org/bot{token}/sendMessage`, отправка после коммита транзакции (`@TransactionalEventListener(phase = AFTER_COMMIT)`). Эта задача **не про реализацию на фронте** — она про **приёмочное тестирование** того, что бэкенд (после реализации BE-16) действительно шлёт сообщения, которые корректно открывают Mini App.

## Требования (на момент появления BE-16)
Таблица событий (раздел 4.6, решение 2026-09-29 п.4 — все события в Telegram, отмеченные ещё и на email):

| Событие | Текст | Кнопка | Email |
|---|---|---|---|
| Верификация | «Ваш аккаунт подборщика подтверждён. Можно создавать отчёты» | «Открыть приложение» → `MINIAPP_URL` | ✅ |
| Бан | «Аккаунт заблокирован: {reason}» | — | ✅ |
| Одобрен и опубликован | «Отчёт {марка модель} опубликован и доступен покупателям» | «Открыть отчёт» → `/reports/{id}` | ✅ |
| На доработку | «Отчёт {марка модель} требует правок: {reason}» | «Исправить» → `/reports/{id}` | — |
| Удалён | «Отчёт {марка модель} снят с продажи модератором: {reason}» | — | — |
| **Продажа** | «Ваш отчёт {марка модель} купили. +{сумма} BYN к выплате» | — | — |
| Выплата сформирована | «Выплата за {месяц}: {сумма} BYN готова к оплате» | — | ✅ |
| **Выплата оплачена** | «Выплата за {месяц}: {сумма} BYN переведена» | — | ✅ |
| Новый спрос (позже) | «N человек ждут отчёт по {марка модель}» | «Смотреть спрос» → `/demand` | — |

«Продажа» и «Выплата оплачена» сейчас **вообще не вызываются** в коде (не просто нет канала Telegram — события не генерируются).

Кнопка — `reply_markup` с `inline_keyboard: [[{ text, web_app: { url } }]]` (работает только в личном чате с ботом — это наш случай) либо обычная `url`-кнопка на `MINIAPP_DIRECT_LINK?startapp=report_<id>`.

### Тест-план приёмки
- верификация, бан, одобрение, доработка (с причиной), удаление, продажа — каждое даёт сообщение в Telegram подборщику;
- отмеченные в колонке «Email» — дополнительно письмо;
- «Исправить» из уведомления о доработке открывает нужный отчёт **с причиной** (требует и BE-16, и BE-8 вместе);
- если подборщик заблокировал бота — ошибка только в логе, модерация не ломается;
- уведомление не уходит, если транзакция откатилась;
- проверка в тестовом окружении Telegram (`TELEGRAM_TEST_ENV`).

## Acceptance Criteria
- [ ] каждое событие из таблицы 4.6 даёт сообщение в Telegram подборщику, отмеченные в «Email» — ещё и письмо
- [ ] «Исправить» из уведомления о доработке открывает нужный отчёт с причиной
- [ ] если подборщик заблокировал бота, это не ломает модерацию (ошибка только в логе)
- [ ] уведомление не уходит, если транзакция откатилась

## Gotchas
1. **Это не задача фронта/бота в узком смысле** — реализация целиком на бэкенде (BE-16), здесь только приёмка и согласование текстов/кнопок с тем, что уже реализовано в Mini App (MINI-18) и боте (BOT-02).
2. **«Продажа» и «Выплата оплачена» не реализованы вообще**, не только без Telegram-канала — события не вызываются в коде ни для одного канала.
3. Отправка должна быть **после коммита транзакции** — иначе откат транзакции не отменит уже отправленное сообщение (явное требование к реализации BE-16, важно для приёмки — тест «откат → нет сообщения»).
4. web_app-кнопки в сообщениях работают только в личном чате с ботом — для рассылок в группы использовать обычную `url`-кнопку на Direct Link.
