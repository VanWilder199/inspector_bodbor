# MINI-17: Проверка, превью и отправка на модерацию

## Цель
Подборщик видит, что осталось заполнить, видит превью отчёта и отправляет его на модерацию.

## Контекст
- **Источник:** `PLAN_FRONTEND_MINIAPP.md`, раздел 1.1 (сценарий G), раздел 2.8 (правила `submit`), раздел 3.7 (адаптер `ReportView`), фича MINI-17
- **Бэкенд:** 🟡 частично — `submit` работает, но `409 REPORT_INCOMPLETE` **без уточнения**, что именно не так (BE-13 — желательное улучшение)

## Зависимости
- MINI-09, MINI-13, MINI-14, MINI-16. 🟡 BE-8 (URL медиа, машина) и BE-13 — улучшения, не блокеры.

## Требования

### Экран `/reports/:id/review`
Flush всех черновиков и ожидание пустой очереди загрузок → перечитывание `GET` → чек-лист готовности → превью `ReportView` через адаптер (раздел 3.7) → MainButton «Отправить на модерацию» (активна только при выполненных блокирующих пунктах) → `popup` с подтверждением → `/reports/:id/done` → удаление черновика.

### Точные правила `submit` (раздел 2.8, проверяются по порядку, первая неудача даёт `409 REPORT_INCOMPLETE` без деталей)
1. Отчёт свой, не удалён, статус `draft` или `revision_required`.
2. **У каждой из 7 секций** `summary != ""` **и** хотя бы один пункт в `report_section_item`. Хватает **одного** пункта на секцию — полноту по справочнику (~45 пунктов) бэкенд не проверяет.
3. Есть **глобальное** видео: `section_id IS NULL`, `kind='VIDEO'`, `status IN ('pending','ready')`. Видео, привязанное к секции, **не засчитывается**.
4. `conclusionText` не пустой, `priceByn IS NOT NULL`.

**Что не проверяется бэкендом:** фото (ни обязательные, ни секционные), замеры ЛКП, полнота пунктов по справочнику, диапазон цены, статус подборщика (`pending`/`banned` отправить могут — фронт сам не пускает их в мастер, см. MINI-05).

### Клиентский чек-лист (таблица 2.8)
| Пункт | Правило | Блокирует отправку |
|---|---|---|
| Секция «X»: итог | `summary.trim() !== ''` | да (бэк) |
| Секция «X»: оценки | `items.length ≥ 1` | да (бэк) |
| Видео обхода | глобальное `VIDEO` в `globalMedia` после confirm | да (бэк) |
| Заключение | `conclusionText.trim() !== ''` | да (бэк) |
| Цена | `priceByn != null` и `≥ 100` (1 BYN) | да (бэк + фронт) |
| Все пункты справочника оценены | по справочнику | нет, предупреждение (станет «да» с BE-5/MINI-22) |
| Обязательные фото | по локальным тегам или BE-11 | нет, предупреждение (станет «да» с BE-11) |
| Замеры ЛКП | ≥ 1 замер | нет, предупреждение |
| Незавершённые загрузки | очередь пуста | да (фронт) |
| Несохранённые изменения | нет `dirty`-черновиков | да (фронт): flush перед отправкой |

**Перед `submit` — обязательный порядок**: flush всех грязных сохранений → дождаться пустой очереди загрузок → перечитать `GET` отчёта → построить чек-лист по **серверным** данным (не по локальному черновику).

### Превью через `ReportView` (раздел 3.7)
Адаптер `toReportViewData(report: ReportDto, localMedia): ReportViewData`:
- свои неотправленные/недавно загруженные фото — `URL.createObjectURL(thumb или blob)` из очереди в памяти; остальные — серверный `url` (требует BE-8, до него — заглушка);
- медиа в очереди добавляются в превью с пометкой «загружается»;
- `stopFactors` — `itemKey` → подпись через `itemLabel()`;
- `header.carTitle` — из данных машины (BE-8), до него — из `avbyUrl` или «Автомобиль»; `inspectorName` — из профиля;
- `showPrice = true`.
Превью строится по **серверным данным после flush**, не по черновику — подборщик видит ровно то, что уйдёт на модерацию.

### Повтор `submit`
`POST .../submit` безопасно повторить при сетевой ошибке: второй вызов после успешного первого вернёт `409 REPORT_NOT_EDITABLE`, что трактуется как успех после перечитывания статуса.

## Acceptance Criteria
- [ ] чек-лист совпадает с серверной проверкой: на отчёте, где фронт показывает «готово», `submit` не получает `REPORT_INCOMPLETE` (набор тест-кейсов по правилам 2–4)
- [ ] видео, привязанное к секции, чек-лист **не** засчитывает
- [ ] пока есть незавершённые загрузки или несохранённые правки, отправка недоступна
- [ ] превью показывает все секции, стоп-факторы (подписи из справочника), ЛКП и медиа, включая локальные
- [ ] при сетевой ошибке `submit` повторяется, `409 REPORT_NOT_EDITABLE` после повтора трактуется как успех после перечитывания
- [ ] после отправки отчёт открывается только на чтение со статусом «На модерации»

## Gotchas
1. **`409 REPORT_INCOMPLETE` без деталей** — клиентский чек-лист обязан сам точно воспроизводить правила 2-4, иначе подборщик увидит «готово» на фронте и ошибку с бэкенда без объяснения. Тестировать специально на граничных случаях.
2. **Видео, привязанное к секции, не засчитывается** — частая ошибка при тестировании (видео должно быть строго глобальным, см. MINI-14).
3. Чек-лист строится **по серверным данным после flush**, не по локальному черновику — иначе можно показать «готово» на основе устаревших локальных данных.
4. Повторный `submit` после сети — `409 REPORT_NOT_EDITABLE` — это успех, не ошибка для пользователя.
