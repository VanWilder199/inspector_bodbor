# MINI-21: Плохой интернет — офлайн-режим и устойчивость (второй этап)

## Цель
Приложение предсказуемо ведёт себя без сети за пределами MVP-упрощений.

## Контекст
- **Источник:** `PLAN_FRONTEND_MINIAPP.md`, раздел 3.6 (плохой интернет), решение 2026-09-29 п. 3 (перенос во второй этап), фича MINI-21
- **Статус:** **второй этап**, явно отложено решением плана. В MVP остаются только баннер офлайна и пауза очереди (уже реализованы в MINI-11).
- **Бэкенд:** не блокирует — это чисто клиентская устойчивость

## Зависимости
- MINI-09, MINI-11, MINI-17

## Требования
- Стор состояния сети (`network: online | offline | degraded`), детект по `navigator.onLine`/`online`/`offline` как подсказка + реальный признак — `TypeError` от `fetch`/`xhr.onerror`/таймаут;
- баннер офлайна (уже частично в MINI-11, здесь — расширение на весь app, не только очередь загрузок);
- `persistQueryClient` для профиля и открытых отчётов — кеш TanStack Query переживает закрытие вкладки/Mini App;
- `networkMode: 'offlineFirst'` для запросов на чтение;
- правила повторов для мутаций (раздел 3.6): идемпотентные `PUT` — через автосохранение с повторами (уже в MINI-09); `POST /inspector/reports` **не** повторяется автоматически (уже в MINI-07); `POST .../submit` можно безопасно повторить (уже в MINI-17); `POST /inspector/register` при повторе даёт `409`, трактуется как успех (уже в MINI-05);
- блокировка создания отчёта без сети (кнопка неактивна, подсказка);
- ручной тест-план «авиарежим на каждом шаге» (документировать, не автоматизировать полностью — часть сценариев требует реального устройства).

## Acceptance Criteria
- [ ] открытый ранее отчёт открывается в авиарежиме, правки копятся локально
- [ ] при появлении сети правки и загрузки уходят без действий пользователя
- [ ] в офлайне нет бесконечных спиннеров, все блокирующие действия объясняют, почему недоступны
- [ ] тест-план пройден на iOS и Android

## Gotchas
1. **Это расширение, а не новая логика** — большинство правил повтора для конкретных мутаций уже реализовано в соответствующих MVP-задачах (MINI-05/07/09/17). Здесь — системный стор состояния сети и `persistQueryClient`, а не повторная реализация retry-логики.
2. Не начинать эту задачу раньше MVP-функциональности — явно отложено решением 2026-09-29 п.3, приоритет ниже всех MVP-фич.

## Промпт для агента
```
Реализуй системную офлайн-устойчивость согласно MINI-21-offline-resilience.md (второй этап, после MVP).

Перед началом убедись, что MINI-05, MINI-07, MINI-09, MINI-11, MINI-17 уже реализованы — эта задача расширяет их, не заменяет.

1. Стор состояния сети: online/offline/degraded, детект через navigator.onLine + TypeError от fetch/xhr.onerror/таймаут
2. persistQueryClient для TanStack Query (профиль, открытые отчёты) — переживает закрытие Mini App
3. networkMode: 'offlineFirst' для запросов на чтение
4. Системный баннер офлайна на уровне приложения (не только в очереди загрузок, как в MINI-11)
5. Блокировка создания нового отчёта без сети с понятной подсказкой
6. Документируй ручной тест-план «авиарежим на каждом шаге мастера» в apps/inspector/README.md

Проверь acceptance criteria, включая ручной прогон на iOS и Android (или укажи, что требуется ручная проверка на реальных устройствах).
```
