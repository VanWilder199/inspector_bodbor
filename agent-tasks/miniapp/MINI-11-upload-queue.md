# MINI-11: Очередь загрузок в памяти, повтор (MVP)

## Цель
Загрузки переживают плохую сеть, пока Mini App открыт (решение 2026-09-29, п. 3 — упрощённая MVP-версия, не полная IndexedDB-реализация).

## Контекст
- **Источник:** `PLAN_FRONTEND_MINIAPP.md`, раздел 3.4 (очередь загрузок, решение MVP), фича MINI-11
- **Бэкенд:** 🟡 частично (те же эндпоинты, что MINI-10). 🟡 BE-8 желателен — без него фото после перезапуска Mini App не видны (только `s3Key`, URL нет).

## Зависимости

## Требования

### MVP-модель (важно: НЕ IndexedDB)
Задачи лежат в сторе **в памяти** (zustand без `persist`), `blob` — в памяти. Жизненный цикл, параллельность, backoff — полная версия из плана. IndexedDB, восстановление очереди после закрытия, квота — перенесены в MINI-23 (второй этап).

```ts
interface UploadTask {
  id: string;
  reportId: string;
  sectionId: string | null;
  kind: 'PHOTO' | 'VIDEO';
  contentType: 'image/jpeg' | 'video/mp4';
  tag?: 'ODOMETER' | 'VIN_PLATE' | 'INSPECTOR_WITH_CAR' | 'DOCUMENTS';
  blob: Blob;
  thumb?: Blob;
  state: 'queued' | 'presigning' | 'uploading' | 'confirming' | 'done' | 'failed';
  s3Key?: string; uploadUrl?: string; presignedAt?: number;
  progress: number;
  attempts: number; lastError?: string;
  createdAt: number;
}
```

### Жизненный цикл
```
queued → presigning → uploading (XHR PUT, progress) → confirming → done
```
- **Параллельность:** 2 фото одновременно, видео строго одно и не параллельно с фото.
- **Повтор:** экспоненциальный backoff 2→4→8→16→30 с (с jitter), без лимита попыток при сетевых ошибках. На `4xx` от API (кроме `401`/`408`) — задача в `failed`, ждёт ручного «Повторить»/«Удалить».
- **Протухший URL:** `Date.now() - presignedAt > 50 мин` или S3 ответил `403` → новый presigned URL с тем же `fileName` (ключ тот же, перезапишется).
- **Confirm после сбоя:** сначала `GET` отчёта (см. MINI-10). `404 MEDIA_NOT_FOUND` на confirm → объект не дошёл до S3 → задача обратно в `uploading`.
- **Офлайн:** пауза, возобновление по `online`, успешному запросу к API, или `activated`.
- **UI:** миниатюра с кольцом прогресса и статусом, общий индикатор «Загружается N из M» в шапке мастера, экран/шит `/uploads` со списком и «Повторить»/«Удалить из очереди».
- **Closing confirmation и баннер** «Не закрывайте приложение, идёт загрузка N фото», пока очередь не пуста.
- **Если всё же закрыли:** незагруженные фото нужно выбрать заново — экран секции показывает, чего не хватает, **по серверным данным** (не по памяти, которая исчезла).

## Acceptance Criteria
- [ ] в авиарежиме фото встают в очередь, после включения сети грузятся сами (приложение открыто)
- [ ] при попытке закрыть Mini App с активной очередью Telegram спрашивает подтверждение
- [ ] `4xx` от API переводит задачу в `failed` с кнопками «Повторить» и «Удалить»
- [ ] индикатор показывает «N из M»
- [ ] после перезапуска Mini App уже загруженные фото видны (по серверному `url`, если BE-8 готов — иначе заглушка «фото загружено»), недогруженных нет, и это видно на экране секции

## Gotchas
1. **Это MVP-версия, не финальная.** Очередь в памяти — пропадает при закрытии Mini App. Не путать с MINI-23 (IndexedDB, второй этап) — там же восстановление после закрытия.
2. Видео никогда не параллелится с фото — иначе забивается мобильный канал.
3. Без BE-8 после перезапуска видно только «фото загружено» (заглушка), а не сами фото — это ожидаемое ограничение MVP, не баг.
4. `401`/`408` не переводят задачу в `failed` сразу — это частный случай (сессия истекла / таймаут), не окончательная ошибка.
