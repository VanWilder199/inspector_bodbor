# MINI-15: Замеры ЛКП

## Цель
Ввод толщины ЛКП по 15 панелям кузова.

## Контекст
- **Источник:** `PLAN_FRONTEND_MINIAPP.md`, раздел 2.7 (`PUT .../paint`), раздел 5 BE-6, фича MINI-15
- **Бэкенд:** 🟡 эндпоинт `PUT` работает, но ❌ **БЛОКЕР**: справочника панелей нет (BE-6) — `panelId` взять неоткуда

## Зависимости
- MINI-08. **Блокер отправки на сервер — BE-6.** До него замеры хранятся только в черновике (localStorage), PUT не выполняется.

## ⚠️ Блокер: это не доработка, это отсутствующий контракт
`paint_panel` (15 строк) заполняется миграцией с `id = gen_random_uuid()` — UUID **разные в каждой базе** (локально, в тесте, в проде), захардкодить их в клиенте нельзя. `GET` отчёта отдаёт только `panelCode` в `paintMeasurements[]`, не `panelId`. Эндпоинта со списком панелей нет. **Решение зависит от бэкенда:** либо `GET /inspector/catalog/paint-panels` (возвращает `{id, code, orderNo}[]`), либо `PaintMeasurementInput` принимает `panelCode` вместо `panelId` (сервер резолвит сам). План допускает оба варианта (раздел 5, BE-6) — **не решать самостоятельно**, писать клиент так, чтобы было легко переключить, когда решение будет принято на бэкенде.

## Требования

### Экран `/reports/:id/paint`
Схема кузова `PaintDiagram` из `@podbor/ui` (тап по панели) + список панелей в порядке `orderNo` с подписями `PANEL_LABELS` (`packages/ui/src/report/catalog.ts` — уже существуют), ввод мкм (числовая клавиатура), несколько точек на панель (`spot`), заметка, мгновенная подсветка по шкале `paintLevel()`, автосохранение полным списком.

Коды панелей из seed (`order_no`): `HOOD(1) ROOF(2) TRUNK(3) FRONT_BUMPER(4) REAR_BUMPER(5) FENDER_FL(6) FENDER_FR(7) FENDER_RL(8) FENDER_RR(9) DOOR_FL(10) DOOR_FR(11) DOOR_RL(12) DOOR_RR(13) SILL_L(14) SILL_R(15)`.

### Контракт (раздел 2.7)
Тело: `{ measurements: [{ panelId, spot?, thicknessUm, note? }] }`. `panelId` — `@NotNull UUID`; `thicknessUm` — `@NotNull Integer`, диапазон не проверяется (`0`, `-5`, `100000` проходят — фронт валидирует 1-5000). Несколько замеров на одну панель разрешены. **Полная замена на весь отчёт**: отправлять всегда полный список по всем панелям. Проверка панелей на бэкенде: все `panelId` должны существовать, иначе `404 PANEL_NOT_FOUND`. Пустой `measurements: []`, скорее всего, тоже даёт `500` — не отправлять.

Для отправки на модерацию замеры **не обязательны** (чек-лист MINI-17 показывает их как предупреждение, не блокер).

## Acceptance Criteria
- [ ] все 15 панелей из справочника, `panelId` берётся из ответа BE-6 (или отправляется `panelCode`, если выбран этот вариант контракта)
- [ ] `PUT` содержит полный список замеров по всем панелям
- [ ] значения вне 1–5000 мкм не принимаются на фронте
- [ ] после перезагрузки замеры восстанавливаются из `GET` (сопоставление `panelCode` → панель)
- [ ] пустой список не отправляется
- [ ] **до появления BE-6**: замеры сохраняются только в черновике, PUT на сервер не выполняется, UI явно показывает «сохранено на устройстве» без попытки отправки

## Gotchas
1. **`panelId` взять неоткуда — явный блокер, не доработка-удобство.** Любая попытка «временно похардкодить UUID» ломается при смене окружения (другая база — другие UUID).
2. **До BE-6 эта фича физически не может сохранять на сервер.** Не изобретать обходной путь (например, угадывание UUID через побочный эндпоинт) — ждать решения.
3. Полная замена — весь список по всем 15 панелям в каждом PUT, как и для секций (MINI-09).
4. MSW-моки должны использовать **случайные UUID** для контракта BE-6 — чтобы тест-код не завязывался на конкретные значения, которых не будет в реальной базе.
